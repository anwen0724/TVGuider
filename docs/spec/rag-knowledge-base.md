# 一、本次开发目标

建立面向 **setup、hold 时序问题**的本地 RAG 知识库构建与独立检索能力。将英文 Markdown 资料转换成可追溯的知识片段，建立向量与 BM25 索引，根据英文查询返回相关片段，为后续修复结果生成提供知识依据。

本次包含：

- 英文 Markdown 资料的读取、校验、结构解析与分块；资料内容覆盖 setup、hold，不限定 FPGA、ASIC 或某个工具，但具体策略保留其适用环境和限制。
- 本地 Qwen3-Embedding-0.6B 编码、Qdrant 本地持久化和本地 BM25 索引。
- 知识库全量构建与重建、失败时保留旧版本、构建配置与来源追踪。
- `dense`、`bm25`、`hybrid` 三种检索模式，Python 接口和共用同一实现的命令行入口。
- 功能验收，以及独立英文评估集上的检索效果验收。
- 基础版使用的原始资料准备：由助手检索网上相关资料、核对来源并整理成若干英文 Markdown，作为构建输入；这项准备工作与运行时构建程序分开。

本次不包含 CDC、PDF/Word/OCR 解析、自动语言识别或翻译、入库时的大模型抽取与改写、embedding 微调、reranker、增量更新、管理界面和多用户检索服务。TVIR 构建、根因分析、生成修复 RTL、STA 与功能验证由其他模块或集成任务承担。

交付后应能独立构建和检索知识库，不依赖 TVIR 或修复生成模块已经实现；检索结果不代表策略适用于所有设计，也不代表 RTL 修复已经成功。

# 二、开发方案设计与要求

## 2.1 功能定义

| 能力 | 触发方与条件 | 输入 | 最终结果与成功条件 | 无法完成的定义 |
| --- | --- | --- | --- | --- |
| 构建／重建知识库 | 开发者通过 Python 或命令行显式调用；首次使用或资料、构建配置变化后执行 | Markdown 目录、知识库位置、构建配置 | 片段、向量、BM25 索引及构建记录完整一致，发布为当前可检索版本，返回构建摘要 | 输入或数据校验失败、无法按规则分块、模型或存储失败，均不得发布部分结果 |
| 独立检索 | 开发者或后续上游模块通过 Python 或命令行调用 | 英文查询、知识库位置、模式、`top_k` 及检索配置 | 使用同一成功构建版本，返回排序后的结果及出处；有效的 BM25 空结果也属于成功 | 非法输入、索引缺失或版本不一致、所需模型或存储运行失败时返回明确错误 |

检索输入是普通英文文本。后续由调用方将 TVIR、根因和约束组织成查询；本模块不定义 TVIR schema，也不自行调用根因分析或 DeepSeek。第一版按文本相似性和词项匹配检索，不宣称已实现设计约束适用性的自动判定。

## 2.2 数据模型

### 2.2.1 原始文档

原始 Markdown 由资料维护者创建与修改，构建程序只读取，不改写源文件。使用 UTF-8；构建递归读取输入目录内的 `.md` 文件。

文档开头必须有 YAML 文档头：

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | string | 必填、非空；当前知识库内唯一的稳定文档标识，文件改名不要求改变该值 |
| `title` | string | 必填、非空；英文文档标题 |
| `topics` | list[string] | 必填、非空；值只能为 `setup`、`hold`，可以同时包含两者 |
| `sources` | list[string] | 必填、非空；可追溯的来源链接列表 |

例如：

```yaml
---
id: setup-pipelining-considerations
title: Pipelining Considerations for Setup Timing
topics:
  - setup
sources:
  - https://docs.amd.com/r/en-US/ug949-vivado-design-methodology/Pipelining-Considerations
---
```

示例仅说明格式，不替代待准备的原始资料。来源列表描述整份文档的参考资料；具体章节在正文中保留对应引用。构建不联网重抓来源内容，也不把来源列表中的每一项自动当作支持所有片段的证据。适用器件、工具、约束和策略影响写入正文。

构建时还需记录源文件路径及内容指纹，用于定位错误和标识实际索引的数据版本。有效正文指文档头和标题以外至少有非空内容，如段落、列表、代码或表格；仅含元数据、空白或标题的文件不满足要求。

### 2.2.2 知识片段

| 数据 | 类型与可选性 | 语义与约束 |
| --- | --- | --- |
| 片段 ID | 非空 string，必有 | 两套索引共用的唯一标识；同一输入与构建配置下可稳定复现，不能只依赖不稳定的遍历顺序 |
| 文档 ID、文档标题、文件路径 | string，必有 | 指向构建版本中的原始文档 |
| 标题路径 | list[string]，必有，可为空 | 保留所属 Markdown 标题层级；没有标题的内容仍保留文档标题作为上下文 |
| 正文 | 非空 string，必有 | 来源于文档的完整或按规则切分的内容，保留列表、代码及表格格式与引用 |
| `topics`、来源链接 | list[string]，必有 | 继承所属文档元数据，正文中的具体引用继续保留 |
| 原始位置 | 源文件行号／范围，必有 | 支持定位与回查；拆开的代码片段必须能追溯原始代码行 |
| 原始结构单元标识 | string，涉及代码／表格时必有 | 将同一代码块或表格拆出的片段关联起来 |
| 代码语言 | string 或空值 | 从源代码围栏读取；源文档没有标注时不猜测 |
| 实际编码文本与 token 数 | string 与正整数，必有 | 编码文本包括加入的标题上下文和实际保留的格式；按固定 Qwen tokenizer 计数，不超过生效上限 |

片段由构建程序派生，不作为独立于原文的人工作者知识条目维护。相同文字出现在不同文档或位置时仍可产生不同片段；检索按片段 ID 去重，不做跨来源的语义去重。资料或分块配置变化可能使片段 ID 改变，旧结果需结合其构建标识回查。

### 2.2.3 构建配置与版本记录

| 配置 | 本版选择／默认值 | 约束 |
| --- | --- | --- |
| embedding 模型 | `Qwen/Qwen3-Embedding-0.6B` | 本地运行；固定并记录实际模型与 tokenizer revision |
| 向量维度 | 1024 | 同一构建中的文档与查询使用匹配的输出配置 |
| 最大片段长度 | 1024 tokens | 可配置正整数；含标题、重叠、代码围栏、重复表头等实际编码文本，不能超过模型与运行配置允许的长度 |
| 正文最大重叠 | 128 tokens | 可配置非负整数且小于片段上限；实际重叠可以少于此值或为零 |
| 编码配置 | 固定并记录 | 包括查询／文档的编码约定、归一化与相似度度量、实际精度等影响结果的配置 |
| BM25 配置 | 固定并记录 | 包括 2.4 定义的文本处理规则、算法实现版本和实际评分参数 |

每次构建保存独立构建标识、源文档清单及指纹、片段数量、构建配置、模型／tokenizer 版本和索引格式版本。查询使用当前成功构建所对应的模型与编码配置，不允许混用另一套向量空间。

### 2.2.4 检索配置与结果

| 字段 | 类型与默认值 | 约束 |
| --- | --- | --- |
| 查询 | 非空 string，无默认值 | 英文约定；去除首尾空白后不能为空，不做自动翻译 |
| 模式 | enum，默认 `hybrid` | 仅允许 `dense`、`bm25`、`hybrid` |
| `top_k` | int，默认 5 | 正整数；表示最终结果数量上限，不要求凑满 |
| 混合检索每路候选数 | int，默认 `max(20, top_k)` | 两路分别使用同一数量上限；若显式配置，不得小于 `top_k` |
| RRF 常数 | 正数，默认 60 | 两路等权；实际值记录在检索／评估配置中 |

检索响应包含当前构建标识、生效模式与参数、有序结果列表。每项结果至少包含片段 ID、正文、文档信息、标题路径、来源、原始位置、最终排名与分数；混合模式另带向量排名和 BM25 排名，未进入某一路候选时该排名为空。

排名从 1 开始。`dense` 与 `bm25` 的分数来自各自检索方式，`hybrid` 的最终分数来自 RRF；不同模式的分数不直接比较，任何分数均不表示修复策略正确的概率。

### 2.2.5 持久化、变化与兼容

原始 Markdown 是知识来源，片段和索引是可重建产物。向量使用 Qdrant 本地持久化；BM25 索引、片段元数据和构建记录保存在本地。不要求新增关系数据库，具体派生文件格式与内部目录组织由实施计划安排。

每个可检索版本必须包含一致的文档清单、片段、向量和 BM25 索引。两套索引的片段 ID 都能解析到该版本的片段数据。重启程序后可加载已发布版本，不重新解析原始资料。

新增、修改、删除源文档均通过显式全量重建生效；重建完成后，被删除文档及旧内容不得继续出现在当前检索中。发布新版本前不覆盖当前可用版本；失败或中断产生的半成品不能成为当前版本。构建程序负责保存派生数据、释放模型和存储资源，并处理本次失败留下的临时产物。

`legacy/` 材料不自动迁入知识库。模型、分块或索引格式变更需重建派生数据；不静默迁移或混用不兼容索引。模型和分词器使用固定版本，依赖升级不自动改变已构建知识库的编码语义。对旧构建的长期留存和多版本查询不在本版承诺范围。

## 2.3 接口定义

### 2.3.1 对外提供

以下定义操作契约，不预先规定 Python 文件、类名或命令名。

| 操作 | 调用方 | Input | Output | 错误结果 |
| --- | --- | --- | --- | --- |
| 构建／重建 | 开发者、资料维护流程 | 资料目录、知识库位置、构建配置 | 构建标识、文档数、片段数、生效配置和成功信息 | 明确原因；涉及资料时给出文件与字段或位置，超长时给出 token 数；不得返回可用的新版本标识来冒充成功 |
| 检索 | 开发者、后续上游模块 | 英文查询、知识库位置、模式、`top_k`、可选检索配置 | 2.2.4 定义的有序结果与构建信息 | 非法输入、知识库不可用、索引不一致、模型或存储失败应与有效空结果区分 |

Python 接口与命令行使用同一套业务实现和默认值。命令行成功与失败应有可区分的退出状态，并展示可读的结果或错误；Python 调用方能够取得结构化结果和可识别的失败类别。具体序列化方式、异常类型及 CLI 参数拼写由实施计划落实，不改变上述语义。

### 2.3.2 外部依赖

| 依赖能力 | 操作与 Input | Output | 失败处理 |
| --- | --- | --- | --- |
| 本地文件系统与 Markdown/YAML 解析 | 读取 UTF-8 文档，解析文档头、标题、正文结构和位置 | 校验后的文档和结构单元 | 文件不可读、编码错误、文档头不合法或正文无效时构建失败 |
| Qwen tokenizer 与 embedding 模型 | 计数与编码片段／查询；使用固定的对应编码约定 | token 数与 1024 维向量 | 加载或编码失败时当前操作失败；不得用假向量或静默截断代替 |
| Qdrant 本地存储 | 写入片段 ID 与向量，持久化、加载和相似性检索 | 与构建版本关联的向量候选及分数 | 写入／加载／查询失败时当前操作失败 |
| BM25 实现 | 同规则处理文档和查询，构建／加载词项统计并检索 | 有词项匹配的候选及分数 | 索引错误时失败；无匹配是成功的空结果 |

模型下载与依赖安装属于运行环境准备。构建处理已提供的 Markdown，不内置网上搜索、爬取或来源内容生成。BM25 单独检索不依赖模型推理；dense 与 hybrid 在查询时需要对应 embedding 模型。各模式都必须使用完整一致的成功构建版本。

## 2.4 业务规则

### 2.4.1 输入与资料范围

递归读取资料目录中的 Markdown；非 Markdown 文件不作为知识输入。没有 Markdown、任一文档缺失必填字段、字段类型或 `topics` 值不合法、文档 ID 重复、任一文档没有有效正文时，整个构建失败，不跳过错误文档后宣称完整构建成功。

资料正文、标题、策略说明、示例注释、查询与检索评估样例统一英文；代码标识符和技术符号按原义保留。不自动识别或翻译语言，也不通过关键词自动判断正文是否涉及 CDC。资料准备环节负责 setup／hold 范围与来源核对。

正文保留适用环境和条件。旧实验中的模型输出只能作为待审阅材料，不能直接标注为已验证修复案例。

### 2.4.2 Markdown 结构与正文分块

先按 Markdown 标题划分章节，保留标题路径；代码围栏内的字符不作为 Markdown 章节标题解释。正文递归拆分优先级为 **段落 → 句子 → 单词 → 字符兜底**，仅对超过长度预算的单元使用更细边界，随后按原始顺序组成不超过上限的片段。短章节不凑满，不跨章节合并正文。

句子边界识别必须考虑英文缩写和小数，不能把所有句点都当作断句位置。普通正文字符兜底只解决无可用自然边界的超长连续内容，不用于拆开受保护的代码行或表格行。

片段长度按 Qwen tokenizer 对实际编码文本计数，默认最多 1024 tokens；标题、重叠文本、代码围栏和重复表头均占用预算。token 数与向量维度是两个独立配置，不根据 1024 维推导片段长度。

### 2.4.3 重叠

同一章节中连续的正文片段，可以在后一块开头重复前一块末尾的完整句子或段落，默认最多 128 tokens。以不超过重叠预算的完整末尾段落或句子作为重复内容；没有可用完整单元时重叠为零，不强行截取半句。

重叠后仍须满足片段上限，并包含新的正文，不能产生只含重复内容的片段。不跨章节重叠，不跨代码／表格重复其他正文；代码拆分不额外重复代码行，表格仅重复其表头结构。

### 2.4.4 代码与表格

代码块或表格在当前片段剩余空间不足、但自身连同标题等上下文能满足上限时，整体移入下一片段。超长时允许按结构拆分：

- **代码**：按完整源代码行分组，保留语言标记和每块完整的 Markdown 代码围栏；记录所属代码块与原始行号，不插入或改写 RTL 语句。片段不保证能独立编译。
- **表格**：按完整数据行分组，每块重复表头及 Markdown 分隔行，保留所属表格标识，不拆开单元格。
- 所有拆分片段仍不得超过生效上限；不得在 tokenizer 或模型调用中再次静默截断。

当一行代码加必要上下文，或表头加单行数据及必要上下文，本身就超过上限时，构建失败并报告文件、位置和实际 token 数。不得截断、跳过或丢弃该行。只有标题／必要包装就使正文无法容纳时同样报告无法分块，不进入不推进的递归。

### 2.4.5 编码与 BM25

文档与查询使用同一固定版本的 Qwen3-Embedding-0.6B 及匹配配置，按该模型文档／查询各自的编码约定执行；使用同一模型不意味着强行给文档和查询加相同前缀。向量维度为 1024。

BM25 对两端统一小写，提取英文单词、数字及下划线代码标识符；`data_valid` 作为完整词项保留，不做词干提取或停用词删除。BM25 有效候选必须至少匹配一个查询词项；不能仅按实现返回的零分或负分与否代替“是否有词项匹配”的判断。

向量相似度度量、归一化约定和 BM25 评分参数在实际实现中固定并记录，评估与使用不得暗中切换算法或参数。具体数值精度和依赖选择属于实施落实，不能改变本节已定义的分词、候选与排序契约。

### 2.4.6 排序、融合与空结果

- `dense`：按向量相似性排序，返回最多 `top_k` 个片段。不设置最低相关性阈值，结果仅表示最相似的候选。
- `bm25`：按 BM25 分数排序，返回最多 `top_k` 个有词项匹配的片段；无匹配返回空列表，不补零匹配片段。
- `hybrid`：默认两路各取 `max(20, top_k)` 个候选；按片段 ID 求并集，计算等权 RRF，再取最终前 `top_k` 条。

RRF 规则为：

```text
score(chunk) = sum(1 / (60 + rank_i(chunk)))
```

只累加片段实际进入的候选列表，排名从 1 开始。未命中某一路时该路贡献为零；常数采用生效配置，默认 60。两路内部和最终结果出现同分时均按片段 ID 升序处理。相同片段只返回一次，不按来源文档去重，因此同一文档的多个片段可以共同进入 Top-K。

最终结果不足 `top_k` 时返回实际数量。BM25 无匹配时 hybrid 仍可融合向量候选，这是正常空结果处理；任何一路运行失败则 hybrid 失败，不能把运行失败当作无匹配而静默退化。

### 2.4.7 规则优先级

实际编码长度上限和不静默丢失原文优先；代码行／表格行完整性与上限无法同时满足时按明确错误处理。重叠服从片段上限和新的正文推进要求。构建版本一致性优先于返回部分检索结果，参数和依赖错误必须与成功空结果区分。

## 2.5 状态与流程

### 2.5.1 状态变化

| 初始状态 | 触发与条件 | 结果 |
| --- | --- | --- |
| 无可用知识库 | 发起构建 | 进入构建中，尚无可检索版本 |
| 有成功版本 A | 发起重建 B | B 独立准备；A 不被半成品覆盖 |
| 构建中 | 所有派生数据完成且一致性检查通过 | 整体发布新版本，返回成功摘要 |
| 构建中 | 校验、解析、分块、模型、存储失败或进程中断 | 不发布新版本；有 A 时仍保留 A，无 A 时仍无可用知识库 |
| 有成功版本 | 发起合法检索 | 使用该版本返回结果，不改变资料或索引 |

不允许半成品成为当前版本，不允许向量、BM25 和片段数据分别来自不同构建。此处约定版本发布和失败后的可用性，不承诺多进程并发查询或无停机服务。

### 2.5.2 构建主流程

1. 校验目录和配置，递归发现 Markdown，记录本次输入及版本信息。
2. 读取并校验文档头、唯一 ID 和有效正文，解析结构及原始位置。
3. 按章节、递归正文规则和代码／表格规则生成片段，核对最终 token 数及来源关联。
4. 使用本地模型编码片段，建立 Qdrant 向量索引；使用同一组片段建立 BM25 索引。
5. 保存片段与构建记录，检查数量、片段标识关联及版本一致性。
6. 整体发布新版本，返回构建摘要。之前的失败或中断不允许通过第 6 步。

重复构建是全量重建，不向旧索引追加重复片段。同一源文档与配置应生成一致的片段及关联关系；每次构建记录可以有不同的构建标识。

### 2.5.3 检索主流程

1. 校验查询、模式、`top_k` 及候选／融合配置。
2. 加载当前成功版本，验证片段、两套索引与记录一致。
3. 按模式执行查询编码及向量检索、BM25 检索，或两者。
4. 排序；hybrid 按 ID 合并并计算 RRF；应用稳定的同分规则。
5. 截取最终 Top-K，附上原文、位置、来源和构建信息返回，不生成答案或修复代码。

### 2.5.4 异常与恢复

| 异常 | 可观察结果与恢复方式 |
| --- | --- |
| 输入／文档不合法 | 报告具体参数、文件或字段；修正后重新调用 |
| 最小代码行或表格行超限 | 报告位置和 token 数；修改资料或显式调整配置后全量重建 |
| 模型／存储失败 | 报告失败环节；修复环境后重新执行，不返回伪造向量或伪成功 |
| 构建中断 | 下次加载只使用已发布版本；清理未完成产物并重新全量构建，不从半成品继续发布 |
| 无可用知识库或数据不一致 | 检索失败；完成构建或重建后再检索 |
| BM25 无匹配 | 成功返回空结果；hybrid 可继续使用正常的向量候选 |

## 2.6 验收标准

### 2.6.1 功能行为场景

| 编号／场景 | 给定 | 当 | 那么 |
| --- | --- | --- | --- |
| RAG-01 首次构建 | 合法英文 Markdown，包含 setup、hold 资料及正文、代码、表格 | 通过构建入口运行 | 返回文档与片段数量、生效配置和构建标识；片段可追溯到原文，两个索引关联同一批片段 |
| RAG-02 无效输入资料 | 空目录、空正文、缺字段、非法 topics、重复 ID 或不可读取的文档 | 分别执行构建 | 对应调用失败并给出原因，不跳过坏文档发布部分知识库 |
| RAG-03 正文递归分块 | 超长章节，包含正常段落、长句、超长连续文本、英文缩写和小数 | 构建并检查可检索片段 | 按确认的边界优先级切分，不丢失原文，不跨章节合并，每块实际编码长度不超过上限 |
| RAG-04 正文重叠 | 同一章节产生多个正文片段，分别存在可用和不可用的完整末尾句子／段落 | 分块 | 重叠不超过 128 tokens 且不截半句；无可用完整单元时为零，每块有新正文，总长度合规 |
| RAG-05 代码完整性 | 可容纳的代码块，以及整体超长但每行可容纳的代码块 | 分块 | 前者完整保留；后者按行拆分，围栏与语言标记保留，原始行号与代码块关联可追溯，无行丢失或额外重复 |
| RAG-06 表格完整性 | 可容纳表格，以及整体超长但表头加各数据行均可容纳的表格 | 分块 | 前者完整保留；后者按行拆分，各块重复表头和分隔行，不截断单元格，数据行完整覆盖 |
| RAG-07 最小单元超限 | 一行代码加上下文，或表头加单行数据及上下文仍超过上限 | 构建 | 报错并指出文件、位置和 token 数；不截断、不跳过、不发布新版本 |
| RAG-08 重启持久化 | 已成功构建知识库 | 结束当前进程后重新加载并检索 | 无需重新解析原始 Markdown，即可返回该版本的片段、来源与排名 |
| RAG-09 全量重建 | 成功版本 A，随后新增、修改、删除源文档 | 完成重建 B 并检索 | 当前结果对应 B；被删除文档和被替换的旧内容不再出现在当前索引，重复构建不累积重复片段 |
| RAG-10 失败保护 | 存在成功版本 A | 重建在校验、编码、写入或发布前发生失败／中断 | A 保持可用，部分版本不能被加载为成功知识库；修复后可以全量重建 |
| RAG-11 编码一致性 | 已构建的模型／tokenizer 版本和编码配置 | 检索或尝试加载不匹配的向量索引 | 正常检索采用匹配配置；不匹配时明确失败，不静默截断或使用另一向量空间 |
| RAG-12 BM25 分词 | 查询和正文含大小写变体、数字、`data_valid`、停用词及不同词形 | 执行 BM25 检索 | 两端一致小写并保留下划线标识符，不做词干提取或停用词删除，只返回至少匹配一个词项的候选 |
| RAG-13 三种模式与默认值 | 可用知识库和有效英文查询 | 分别调用三种模式，并调用省略模式与 top_k 的入口 | 返回对应模式的结果；缺省为 hybrid、最多 5 条，可调整 top_k；数量不足时不凑数 |
| RAG-14 RRF 融合 | 两路有交集、各自独有片段及相同分数的候选 | 使用默认混合配置检索 | 两路分别最多取 max(20, top_k)，按从 1 开始的排名及常数 60 融合；按 ID 去重，同分按 ID 升序，最终最多 top_k 条 |
| RAG-15 BM25 无匹配 | 查询没有出现在文档中的词项 | 调用 bm25 和 hybrid | bm25 成功返回空列表；hybrid 可返回向量候选，并将其 BM25 排名标为空，不补零匹配片段 |
| RAG-16 参数与依赖错误 | 空查询、非法模式、非法 top_k、无索引、版本不一致或所需模型／存储失败 | 调用相应操作 | 明确失败并与空结果区分；hybrid 不因一路失败而悄悄改用另一模式 |
| RAG-17 来源与接口一致性 | 同一构建、查询和配置 | 分别通过 Python 与命令行查询 | 使用同一逻辑返回一致的片段 ID 与顺序；结果有正文、标题路径、出处、位置、构建标识及对应排名信息，不生成答案 |

以上场景约束可观察行为；具体测试文件、命令、替身及任务顺序写入 Implementation Plan。模型依赖的模拟测试只能证明错误处理等契约，不能代替真实编码、持久化和检索验证。

### 2.6.2 效果评估

准备 **20 个英文验收问题：setup 10 个、hold 10 个**。另行准备调参查询；最终验收问题及其标签不加入待索引原始资料，不在验收集上反复调参后宣称独立验收。

每个问题预先标注应命中的相关章节，以文档 ID、标题路径及能消除重名歧义的位置关联。相关章节必须包含回答该问题所需的原理、原因或策略，不能仅因出现 setup／hold 词语就标为相关。使用章节标签避免分块变化后重新定义目标答案；片段通过原始位置映射到章节，只有重复标题而没有该章节正文不计为命中。

定义：每个问题的前 5 条结果只要至少一条命中标注的相关章节，该问题记为 1，否则为 0；**HitRate@5 = 命中问题数 / 问题总数**，不是相关片段召回率，也不是修复成功率。

| 编号 | 通过标准 |
| --- | --- |
| RAG-E01 总体检索效果 | 默认 hybrid 配置在固定 20 问上至少命中 16 问，即 HitRate@5 ≥ 80% |
| RAG-E02 分类检索效果 | setup 至少命中 8/10，hold 至少命中 8/10，两项同时满足 |
| RAG-E03 对照结果 | 在同一资料、问题集与 Top-K 下记录 dense、bm25、hybrid 的逐题结果和分类／总体指标；不要求 hybrid 必须胜过每种单独模式 |

验收前固定原始资料、查询与标签版本，记录实际构建标识、模型和 tokenizer revision、分块、编码、BM25、候选数和 RRF 配置、软件版本与执行环境。记录漏检问题及其前 5 条结果，不能只给最终百分比。

相同版本与配置重复评估应能够解释结果变化；实现若引入随机步骤，需要固定随机种子并说明重复运行与汇总方式，不选取多次运行中的最佳值冒充固定结果。模型推理不使用训练模式的随机 dropout。尚未运行本评估，不宣称已达标；若后续使用验收问题指导调参，需记录该集合用途变化并另行准备独立验收集。

### 2.6.3 本份与联合验收边界

本份负责 Markdown → 分块 → 实际 embedding → 两套持久化索引 → 三种检索模式的独立闭环，以及上述功能和效果标准。资料准备和评估集准备属于本份交付条件，不能仅完成接口代码就宣布整个能力验收通过。

后续联合验收由方法主链集成任务负责：根因分析模块提供英文问题描述，修复生成模块消费片段正文、出处及设计上下文。联合任务需要验证查询是否正确表达根因、修复是否正确使用知识，以及最终 RTL 的功能与时序表现。对应 TVIR、根因分析、修复生成接口仍由各自 Spec 定义。

本份通过不证明 TVIR 构建正确、根因判断正确、修复成功或时序收敛；但后续联合验收未开始不能免除本份独立检索与效果验收责任。

# 三、设计选型考量

| 选择 | 考虑过的方案与选择理由 | 当前代价与限制 |
| --- | --- | --- |
| 自行实现领域流程，复用检索组件 | 比较过 RAGFlow、Dify 和轻量 Python 方案；基础版资料数量少，需要可控的分块、实验记录和独立模块接口，选择后者 | 需要自行实现资料校验、构建管理与检索接口，没有现成管理界面 |
| 英文 Markdown 作为唯一输入 | 相较直接解析论文 PDF、Word，Markdown 便于保留和审阅标题、代码、表格与出处 | 网上资料需先整理；英文是使用约定，不由程序自动检测 |
| 常规片段 RAG | 比较过入库时让大模型抽取结构化策略；选择解析、分块、embedding、入库，直接检索原文片段 | 不提供自动知识抽取或语义校验，资料正确性依赖来源和审阅 |
| 本地 Qwen3-Embedding-0.6B、1024 维 | 比较过在线 API、BGE-M3、E5、英文 BGE 和 Nomic；选择 Qwen 的本地可运行、英文与代码检索能力及较长输入支持 | 占用本机资源；官方通用能力不证明 setup／hold 检索效果，需要实际评估 |
| 1024 tokens 上限与结构分块 | 比较过 512 与 1024；选择 1024 作为可配置初始上限，为策略条件与示例保留空间，正文采用递归自然边界切分 | 上限不是最优值的实测结论，也与向量维度无关；调整参数需重建并重新评估 |
| 超长代码／表格按结构拆分 | 比较过特殊块允许超限、完整块一超限就报错；最终选择保持上限，超长代码按行、表格按行并重复表头，只有最小完整行仍超限时报错 | 拆出的代码不能保证独立编译，长距离语义可能分离；原始位置仅提供追溯能力，不自动补回全部上下文 |
| 向量＋BM25，等权 RRF | 比较过纯向量检索；选择同时利用语义和词项匹配，保留三种模式进行排查和对照，暂不加入 reranker | 候选数与常数是初始参数，没有效果保证；无向量阈值时可返回与问题无关但最相似的内容 |
| Qdrant 本地模式与本地 BM25 | 不先部署数据库服务；两套索引共享片段标识，服务单机原型 | 不承诺多用户并发或大规模服务能力；索引一致性与版本管理由项目负责 |
| 全量重建与整体发布 | 相比增量更新，初期资料少，全量重建便于明确删除与更新行为并核对一致性 | 重复编码开销更大，需要准备新版本的临时空间；本版没有自动增量同步 |
| Python 接口＋命令行 | 同一逻辑同时满足独立验收和后续方法接入 | 不提供可视化页面，调用方负责把领域信息组织成英文查询 |
| 20 问、分类 HitRate@5 ≥ 80% | 采用能直接判断知识是否进入前五条的基础标准，setup／hold 分别计分 | 样本规模小，只能证明该固定评估集上的结果，不能外推为全部时序问题的成功率 |

以下为已核实的工具能力和参考资料；本项目采用的阈值、错误处理、源文档格式与验收标准是本次讨论确定的设计，不是这些工具自动提供的全部行为：

- [Qwen3-Embedding-0.6B 官方模型说明](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)：模型支持英文／代码等检索、最长 32K 输入和最高 1024 维向量；实际文档与查询编码需遵循对应约定。领域效果仍需验证。
- [Qdrant Python 客户端](https://github.com/qdrant/qdrant-client)：支持本地持久化原型，不需要单独启动 Qdrant 服务。
- [LangChain Markdown 分块](https://docs.langchain.com/oss/python/integrations/splitters/markdown_header_metadata_splitter)与[递归分块](https://docs.langchain.com/oss/python/integrations/splitters/recursive_text_splitter)：可以组合标题分组与递归切分；默认字符计量不能直接当作本项目的 token 计量，且需要另外保护代码与表格结构。本 Spec 不强制采用 LangChain。
- [Docling 分块说明](https://github.com/docling-project/docling/blob/main/docs/concepts/chunking.md)：提供重复表头及按行拆分思路；本项目对单行超限采用明确报错，不照搬该工具的所有兜底行为。
- [Azure AI Search 分块指南](https://learn.microsoft.com/en-us/azure/search/vector-search-how-to-chunk-documents)给出 512 tokens 起点；[LlamaIndex 默认配置](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/constants.py)采用 1024 tokens。这些只能作为初始参数参考，不证明我们的参数最优。
- [既有平台调研记录](C:/Users/anwen/Desktop/tv-guider/docs/notes/2026-09-24-rag-platform-research.md)保存早期候选比较；其单 setup 起点、知识卡及其他候选建议不替代本 Spec 已确认的 setup／hold、英文原始文档片段方案。
